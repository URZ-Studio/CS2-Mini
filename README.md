# MiniCraft II (CS2-Mini)

> 개발 보관용 · v0.1.7-preview · 2026-11-26 · 누락 유닛, 차원 소환, 사망 모델 및 투영 그림자 보정 / 실게임 미검증

스타크래프트 II: 공허의 유산 섬멸전을 소형 유닛, 작은 건물, 빠른 생산, 대규모 물량전으로 바꾸는 독립 확장 모드(Extension Mod). 기존 테란/저그/프로토스 유지. 기존 섬멸전 맵에 적용하는 것이 목표이며 맵 자체는 수정하지 않는다. 전용 소형 맵은 추후 별도 제작 가능.

## 고정 자동 업데이트 실행기 (2026-11-25)

기존 버전별 BAT/PY 다운로드 절차를 대체한다. 아래 방법이 이전 버전별 사용 방법보다 우선한다.

- `Build-MiniCraft.bat`를 한 번만 원하는 작업 폴더에 저장한다. Git for Windows 및 Python 3가 필요하다.
- BAT는 GitHub 비공개 저장소의 main을 인증된 Git HTTPS 연결로 가져온다. 최초 실행 시 Git Credential Manager 로그인 필요 가능. 인증 토큰을 BAT에 넣지 않는다.
- `.MiniCraft-cache` 안에 Git 캐시와 최신 빌더를 저장하고, `--check` 검사를 통과해야 실행한다. 네트워크/인증/검사 실패 시 기존 모드를 업데이트하지 않는다.
- 이미 게시한 미니크래프트 구성 요소 폴더가 있다면 에디터를 닫고 그 폴더를 BAT에 한 번 끌어 놓는다. 성공 후 대상 경로를 기억하며 다음부터 BAT 더블클릭만으로 같은 폴더를 업데이트한다. 대상을 변경하려면 새 폴더를 끌어 놓는다.
- 신규 사용자 더블클릭 시 고정 폴더 `MiniCraft-II.SC2Mod`를 생성한다. 이후 같은 폴더를 업데이트하며 ZIP 생성은 하지 않는다.
- 기존 모드 업데이트 전 전체 백업을 생성하고 DocumentInfo/Header를 교체하지 않는다. MiniCraft 관리 카탈로그와 관련 텍스트는 새 버전으로 교체한다. 에디터 저장/게시 자체는 수동이다.
- 새 버전 배포 시 빌더 및 데이터만 변경하고, 실행기 자체에 문제가 있지 않으면 BAT는 변경하지 않는다.
- Windows 실제 실행 및 에디터 테스트는 아직 미검증.

## 현재 상태

v0.1은 Python 기반 XML 변경분 자동 생성기이며, 완성된 SC2Mod 파일이 아니다. 기존 설치 파일은 변경하지 않는다. 공개 SC2Mapster 데이터 스냅샷을 받아 변환하거나 로컬 원본을 지정할 수 있다. 원본 버전 차이 및 카탈로그 상속 문제에 주의.

## 재개 / 테스트

1. 보관한 v0.1 ZIP의 압축을 풀고 Python 3.9 이상 환경에서 Build-MiniCraft.bat 실행.
2. 갤럭시 에디터에서 공허의 유산 멀티플레이 의존성을 사용하는 확장 모드를 구성 요소 폴더 형식으로 저장.
3. 생성된 XML 변경분을 빈 모드에 반영하고 카탈로그 등록 확인.
4. 에디터 검사, SC2Mod 저장, 비공개 게시 후 섬멸전에서 검증.
5. build-report.json과 실제 게임 결과를 기준으로 수정.

## 별도 확장 모드 아이디어 (미착수)

아래는 향후 검토할 독립 확장 모드 기획 메모다. 현재 프로젝트의 구현 범위에 포함하지 않으며, 실제 게임 동작 및 에디터 지원 여부는 미검증이다.

### N배 크래프트 (가칭)

- 게임 시작 전 옵션에서 유닛 생산 배수 N을 1~10배 중 선택 (1배는 일반 모드).
- 한 번의 생산 명령으로 기존 생산량의 N배 생성. 생산 비용 및 생산 시간은 기존 생산 명령 1회 기준으로 유지하는 구상.
- 최대 인구 상한은 순정 200 유지. 개별 유닛의 인구 소모를 기존의 1/N로 줄여 한 번의 생산 명령이 차지하는 총 인구수를 유지한다.
- 예: 10배에서 해병 10기 = 인구 1, 저글링 20기 = 인구 1, 시즈 탱크 10기 = 인구 3.
- 건물 건설은 기존대로 유지하고 플레이어와 AI에 동일한 생산 배수를 적용하는 방향.
- 특수 생산(애벌레, 변태, 차원관문 등), 일꾼 적용 범위, 소수점 인구 처리, AI 호환성은 추후 검토.
- 대량 유닛으로 인한 CPU 시뮬레이션, 길찾기 및 프레임 저하가 예상되므로 배수별 실게임 부하 테스트 필요.

### 데저트 스트라이크 모드 (가칭)

- 건물로 병력 구성을 편성하고 일정 주기마다 해당 유닛을 자동 출격시키는 방식.
- 출격 유닛 대신 생산용 건물이 인구수를 점유한다. 출격 유닛은 인구 소모 없음.
- 출격 병력이 전멸해도 다음 출격 주기에 건물에서 다시 생성하는 구상. 건물 철거 시 점유 인구 반환.
- 자동 이동 및 전투, 건물별 유닛 대응, 배치, 출격 주기, 경제, 생존 병력의 누적 여부, 승리 조건 및 AI 지원은 추후 설계.
- 독립 모드로 검토하며 기존 MiniCraft II 및 SmartCraft AI의 기본 규칙은 변경하지 않는다.

## v0.1.1 Preview — 구성 요소 빌드

직접 패키징한 SC2Mod 파일이 에디터에서 열리지 않는 문제가 보고되어, 기존 프리뷰의 XML 변경 데이터와 구성 요소 메타데이터를 저장소 내 재생성 가능한 소스로 보관한다. 에디터/실게임 정상 동작은 아직 확인되지 않았다.

1. 이 저장소를 내려받거나 git clone한다.
2. Python 3가 설치된 Windows에서 `Build-MiniCraft.bat` 실행.
3. 생성된 `MiniCraft-II-v0.1.1.SC2Mod` 폴더의 `ComponentList.SC2Components`를 갤럭시 에디터에서 연다.
4. 에디터에서 다른 이름으로 저장하여 새 SC2Mod 파일로 만든다. 원본 모드는 덮어쓰지 않는다.

생성 데이터: Unit 127개, Actor 71개, Effect 64개, Ability 39개(시간 항목 213개), Race 3개. 일부 상속 필드, 점유 면적, 최소 피해, 업그레이드 증가량, 회복 및 특수 생산, 카메라는 미완료. 현재 빌더는 이전 변경 데이터의 재구성본이며 기존 게임 데이터 전체를 최신 버전으로 재계산하지 않는다. 의존 관계는 VoidMulti, 확장 모드 유형은 Gameplay로 설정했다. 실제 에디터 열기 성공 여부는 미검증이다.

## v0.1.2 — 첫 실게임 피드백 수정

- 실게임에서 바퀴 체력은 약 14, 공격력은 16으로 관찰됨. 실제 공격 효과 `AcidSalivaU`와 근접 대체 효과 `RoachUMelee` 모두 1.6으로 설정.
- 공개 데이터 6개 계층의 피해 효과와 유닛 → 무기 → 피해 효과 연결을 대조. 피해 효과 수정 항목 64 → 115개, 연결 검사 중 141개 효과를 방문. 일부 무기 링크는 공개 스냅샷에서 미해결이며, 모든 능력 피해/업그레이드 보너스가 검증된 것은 아님.
- 127개 유닛/건물의 반경을 원본 명시값, 상속, 공통 기본값에서 다시 계산. 누락된 Radius/SeparationRadius 등 24개 필드 추가. 바퀴 Radius/SeparationRadius 0.5 → 0.25, InnerRadius 0.625 → 0.3125. 건물의 실제 격자 점유 면적은 아직 별도 작업 필요.
- 기존 71개 행위자의 외형 Scale을 XYZ 3축으로 지정. 확인 가능한 원본 스케일은 0.5배로 계산하고, 원본 명시 스케일 미확인 시 1.0을 기준으로 0.5 지정. Liberty ActorData 전체를 가져오지 못했으므로 실제 표시 크기가 정확히 50%인지 실게임 재검증 필요. 체력/공격력 10%와 외형 50%는 별개.
- 빌더 실행 시 새 `MiniCraft-II-v0.1.2.SC2Mod` 구성 요소 폴더 생성. 기존에 게시 성공한 문서의 의존 관계와 설명을 보존하려면, 해당 문서를 구성 요소 폴더로 저장한 뒤 백업하고 새 폴더의 Base.SC2Data/GameData 내 XML 5개만 교체하여 다시 열고 기존 게시 이름으로 업데이트한다. 생성 폴더 전체를 그대로 사용하면 이전처럼 의존 관계와 설명 설정을 다시 확인해야 한다.

정적 데이터 수정 및 대조 완료. 에디터와 실게임에서 v0.1.2 실행은 미검증. 감사 자료: [유닛 무기 연결](audit/v0.1.2-unit-weapons.json), [무기 효과 연결](audit/v0.1.2-weapon-effects.json).

- 공격력/방어력 업그레이드 73개 정의에 수치 필드 1280개 조정(상속 배열 인덱스 추적 기반; 에디터 확인 필요). 최소 피해 목표 0.05. 자극제 체력 비용 1/2, 회복 효과 일부 조정. 에너지 비용/회복 효율 및 스킬 고정 텍스트 전체 검수는 남아 있음.
- 한국어 담즙/기생 폭탄 툴팁 수정. 다른 고정 문구는 아직 순정 표시일 수 있음.
- 빌더에 XML 파싱, 중복 ID, 주요 공격력/체력/크기/모드 비용/격자 회귀 체크를 추가. 이 버전의 네이티브 게임/에디터 실행 및 Python 빌더 실제 실행은 아직 미검증.

### 기존 게시 모드 업데이트(권장)

1. 이미 게시에 성공한 모드를 갤럭시 에디터에서 구성 요소 폴더로 저장하고 에디터를 닫는다.
2. 최신 저장소의 Build-MiniCraft.bat 위에 그 구성 요소 폴더 자체를 끌어 놓는다.
3. 빌더는 기존 폴더 전체의 백업을 만들고 MiniCraft 카탈로그 8개와 include 목록 및 한국어 툴팁을 갱신한다. DocumentInfo/Header와 게시 설정은 교체하지 않는다. 대상은 이 모드의 전용 구성 요소 폴더여야 하며 다른 모드에 사용하지 않는다.
4. 에디터에서 다시 열고 기존 게시 이름으로 업데이트한다.

BAT를 그냥 실행하면 새 v0.1.3 구성 요소 폴더를 생성한다. 새 폴더는 의존 관계 및 게시 정보 재설정이 필요할 수 있다. `python Build-MiniCraft.py --check`로 데이터 정적 검사를 별도 실행할 수 있다.
